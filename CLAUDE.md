# Пісочниця Творця — архітектура та план розвитку

Сендбокс-симулятор світу в стилі WorldBox: рельєф, погода, стихії, дика
природа. Оригінальний прототип (`reference/god-sim.html`) — один
самодостатній HTML-файл на ~2200 рядків. Цей проєкт — той самий прототип,
перенесений 1:1 (без втрати механік і графіки) у структурований проєкт на
**TypeScript + Vite**, розбитий на домени.

## Швидкий старт

```bash
npm install
npm run dev        # дев-сервер з гарячим перезавантаженням
npm run typecheck  # tsc --noEmit
npm run build      # тайпчек + збірка в один HTML-файл (dist/index.html)
npm run preview    # локально подивитись production-збірку
```

Збірка (`vite-plugin-singlefile`) інлайнить весь JS/CSS прямо в
`dist/index.html` — на виході знову один файл, який можна відкрити без
сервера чи роздати як артефакт, як і оригінал. Зовнішній ресурс лишається
тільки один — шрифт Google Fonts (`Press Start 2P`) через `<link>`, так само
як в оригіналі.

## Чому саме така структура

Оригінал — це одна велика функція-замикання (IIFE), де десятки `let`-змінних
на верхньому рівні (висота рельєфу, час доби, вітер, обраний інструмент,
камера тощо) вільно читаються й пишуться з будь-якого місця файлу. Пряме
"розрізання по копірайту" на ES-модулі тут не працює: JS-модулі забороняють
іншому файлу переприв'язувати імпортовану змінну (`import { x } from ...; x =
5` — помилка), а оригіналу це було потрібно постійно.

Рішення: кожен домен володіє **одним експортованим об'єктом стану**
(`world`, `clock`, `camera`, `uiState`, `creatureState`, `audioState`,
`tileBuffer`…), чиї **поля** мутуються звідусіль без обмежень ES-модулів —
працює так само, як спільні змінні в оригіналі, але з чіткою пропискою
"хто власник". Масиви (`particles`, `animals`, `clouds`, `tornados`…)
експортовані як `const` і мутуються через `push`/`splice`/`.length = 0` —
теж без переприв'язки. Це дало розбити файл на модулі майже без ризику
поведінкових розбіжностей — переважна більшість функцій перенесена
дослівно, лише з заміною `globalVar` на `store.globalVar`.

## Структура

```
src/
  world/       рельєф і його стан: генерація, шум, біоми, константи
  sim/         клітинкова симуляція: вогонь/ріст/лава, погода, тули гравця,
               природні події (блискавка/метеор/смерч), годинник (час доби/вітер)
  creatures/   довідник видів, спавн/життєвий цикл, AI (мозок тварин), рендер тварин
  render/      камера, палітра, текстурний буфер ландшафту, композиція сцени
  audio/       синтезований звук (Web Audio API): рушій, ефекти, фонові звуки
  ui/          DOM-інтерфейс: вкладки/інструменти, HUD, огляд тварини, ввід
  save/        серіалізація світу в localStorage
  main.ts      точка входу: ініціалізація + головний цикл (requestAnimationFrame)
```

### world/
Джерело істини про клітинки сітки: `state.ts` тримає всі типізовані масиви
(`hgt`, `cover`, `biome`, `snow`, `wet`, …) в об'єкті `world`, індекс
клітинки — `y*W+x`, як і в оригіналі. `generate.ts` — процедурна генерація
(fBm-шум із `noise.ts`) висоти/температури/вологості/біомів і початкових
дерев. `constants.ts` — пороги висот, типи покриву/біомів, швидкості росту.

### sim/
`clock.ts` — час доби, вітер, пауза, струс камери/спалах. `simulate.ts` —
клітинковий автомат ландшафту (поширення вогню, тління, застигання лави,
танення снігу, ріст лісу), тікає раз на `TICK` мс, а не щокадру.
`particles.ts` — дощ/сніг/дим/пара/іскри (фізика, без малювання).
`clouds.ts` — фонові й грозові хмари, намокання землі. `events.ts` —
блискавка/метеор/смерч (одноразові події, що б'ють по рельєфу й тваринах).
`tools.ts` — пензлі гравця (`applyTool`) і диспетчер "пострілових"
інструментів (`shootAt`). `worldLifecycle.ts` — оркестрація народження й
перегенерації світу.

### creatures/
`species.ts` — довідник видів (спрайти-піксель-карти, палітри, дієта,
швидкість, зір, розмноження) — 20+ видів: травоїдні, хижаки, морські, повітряні.
`types.ts` — тип `Animal` (стан-машина з набором необов'язкових полів під
кожен стан AI). `habitat.ts` — предикати місцеперебування/їжі, спільні для
спавну й AI. `animal.ts` — народження/спавн/смерть/вибір тварини кліком.
`ai.ts` — "мозок": стани (`wander/eat/drink/flee/stalk/chase/mate/follow/…`),
хижацтво, розмноження, польоти (орел, метелики, кажани, світлячки).
`render.ts` — малювання тваринних спрайтів і емоцій-іконок над ними.

### render/
`context.ts`/`camera.ts` — canvas і математика камери (zoom/pan/pinch,
екран↔тайл). `palette.ts` — кольори рельєфу за висотою/біомом.
`vegetation.ts` — дерева/вогонь/декор, що "запікаються" прямо у піксельний
буфер тайлів. `buffer.ts` — растеризація всього ландшафту в офскрін-canvas
(перебудовується лише коли `dirty`, а не щокадру — це головна оптимізація
оригіналу, збережена як є). `scene.ts` — фінальна композиція кадру: буфер →
тіні хмар → тварини → частинки → ніч/світло → блискавки → курсор.

### audio/
Увесь звук синтезований у браузері (осцилятори + шумовий буфер), без жодного
аудіофайлу. `engine.ts` — примітиви Web Audio (тон, шумовий постріл,
петлі). `sfx.ts` — каталог конкретних ефектів і голосів тварин.
`ambient.ts` — фонові звуки (цвіркуни, тріск вогню) і гучність петель
(океан/вітер/дощ/вогонь/смерч/лава) залежно від того, що видно в кадрі.

### ui/
`tabs.ts` — вкладки категорій інструментів. `icons.ts` — 8×8 піксель-іконки
кнопок. `hud.ts` — кнопки шапки (рух/пензель/день-ніч/звук/пауза/
збереження/новий світ) і текстові індикатори (час, вітер, кількість тварин).
`inspect.ts` — панель огляду обраної тварини. `input.ts` — вказівник:
малювання, "постріл", панорама, pinch-zoom, колесо. `state.ts`/`toast.ts` —
дрібний спільний стан UI без залежностей (щоб уникнути циклів імпортів).

### save/
`save.ts` — серіалізація рельєфу (усі шари клітинок, base64 сирих байтів
типізованих масивів) і спрощеного списку тварин (без сімейних/зграйних
зв'язків — вони відновлюються природним шляхом) у `localStorage`. Кнопки
💾/📂 у шапці. Формат версійний (`version: 1`) — на майбутнє.

## Що навмисно не змінено

- Усі числові константи (пороги висот, швидкості, ймовірності) перенесені
  дослівно — це "відчуття" симуляції, міняти їх не варто без явного запиту.
- Дивні на вигляд деталі оригіналу (наприклад, `frame`/`fc` заморожуються на
  паузі, через що HUD-оновлення може почати спрацьовувати щокадру) збережені
  як є, а не "виправлені" — вони не впливають на геймплей.
- Розмір сітки клітинок фіксується один раз при старті; зміна розміру вікна
  лише масштабує камеру, а не перегенеровує світ (як і в оригіналі).

## План розвитку

Нижче — напрямок, у якому може рости симуляція, від найпростішого до
найскладнішого. Кожен пункт спирається на вже наявну архітектуру доменів.

### 1. Люди — нова істота "нового типу"
Технічно люди — ще один запис у `creatures/species.ts`, але з принципово
іншим AI: не миттєві інстинкти (`hunger→eat`), а *завдання* (принести дрова,
збудувати хатину, обробити землю). Пропонований підхід:
- Новий файл `creatures/humanAi.ts` з чергою завдань (`task queue`) замість
  стан-машини `ai.ts` — люди довговічніші й потребують пам'яті про домівку,
  роботу, родину.
- Ресурси (дерево, їжа, камінь) — нові шари в `world/state.ts`
  (`stockpile` на клітинку споруди) або окрема структура "будівля" в новому
  `sim/buildings.ts`.
- Житло — перша будівля: перетворює клітинку на "дім", дає точку сну/відпочинку.

### 2. Села — групування людей і будівель
- `sim/settlements.ts`: село = центр (ратуша) + прилеглі будівлі + список
  жителів. Розростання села — нові будівлі з'являються біля існуючих, коли
  населення й ресурси дозволяють (аналогічно тому, як зараз ліс розростається
  біля дерев у `simulate.ts`).
- UI: нова вкладка "Люди" в `ui/tabs.ts`, інструмент "заснувати село".
- Село впливає на ландшафт (вирубка лісу для будівництва, витоптування землі —
  вже є механіка `grazed`, її можна перевикористати).

### 3. Королівства — політичний шар над селами
- `sim/kingdoms.ts`: королівство = множина сіл під одним правителем +
  територія (найпростіше — clip-регіон навколо сіл, як `stormArea` для
  гроз). Дипломатія починається з двох станів: мир/війна.
- Кордони можна візуалізувати як напівпрозорий оверлей у `render/scene.ts`
  (окремий прохід, за зразком тіней хмар).
- Зростання/об'єднання королівств — природний наслідок того, що села
  розростаються і стикаються територіями.

### 4. Війни — конфлікт між королівствами
- Юніт "воїн" — ще один AI-профіль людини (`humanAi.ts`), що замість
  завдань мирного часу виконує похід: рух до вражого села, бій (найпростіше —
  та сама механіка "хижак наздоганяє здобич" з `ai.ts`, тільки обидві сторони
  можуть завдавати шкоди).
- Наслідки війни повинні бити по вже наявних шарах: спалені будівлі
  (перевикористати `C_FIRE`/`C_BURNT` з `world/constants.ts`), зруйновані
  поля, біженці (люди, що йдуть шукати нове село — це вже є як патерн
  `findNear`/`toFood` в `ai.ts`).

### 5. Збереження — від локального слоту до повноцінних збережень
Поточний `save/save.ts` — це відправна точка (один слот, `localStorage`).
Далі:
- **Кілька слотів** і мініатюра світу (рендер `tileBuffer` у маленький PNG
  для прев'ю збереження).
- **Експорт/імпорт у файл** (`.json`, можливо стиснутий) — щоб можна було
  ділитися світами між пристроями/людьми.
- **Автозбереження** з інтервалом, з відкатом при пошкодженому файлі.
- Коли з'являться люди/села/королівства — розширити формат збереження
  новими секціями (це нативно ляже на вже версійний формат `version: N`).
- Довгостроково — синхронізація збереження в хмару (потребує бекенду, поза
  межами цього фронтенд-проєкту).
