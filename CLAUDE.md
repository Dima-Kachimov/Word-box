# Пісочниця Творця — архітектура та план розвитку

Сендбокс-симулятор світу в стилі WorldBox: рельєф, погода, стихії, дика
природа і цивілізації (раси, міста, королівства, дипломатія, війни). Оригінальний прототип (`reference/god-sim.html`) — один
самодостатній HTML-файл на ~2200 рядків. Цей проєкт — той самий прототип,
перенесений 1:1 (без втрати механік) у структурований проєкт на
**TypeScript + Vite**, розбитий на домени. Піксельну графіку оригіналу
замінено мультяшною векторною (контури, об'ємні градієнти, плавні береги) —
механіки й числові константи симуляції від цього не змінились.

## Швидкий старт

```bash
npm install
npm run dev        # дев-сервер з гарячим перезавантаженням
npm run typecheck  # tsc --noEmit
npm run build      # тайпчек + збірка в один HTML-файл (dist/index.html)
npm run preview    # локально подивитись production-збірку
```

Збірка (`vite-plugin-singlefile`) інлайнить весь JS/CSS прямо в
`dist/index.html` — на виході знову один файл, який можна відкрити без
сервера чи роздати як артефакт, як і оригінал. Зовнішній ресурс лишається
тільки один — шрифти Google Fonts (`Nunito` для тексту, `Rubik` для
заголовків) через `<link>`; без мережі підставляються системні.

Порт на Godot 4: готові промпти по фазах і специфікація з усіма числами —
`docs/GODOT_PORT.md`.

## Чому саме така структура

Оригінал — це одна велика функція-замикання (IIFE), де десятки `let`-змінних
на верхньому рівні (висота рельєфу, час доби, вітер, обраний інструмент,
камера тощо) вільно читаються й пишуться з будь-якого місця файлу. Пряме
"розрізання по копірайту" на ES-модулі тут не працює: JS-модулі забороняють
іншому файлу переприв'язувати імпортовану змінну (`import { x } from ...; x =
5` — помилка), а оригіналу це було потрібно постійно.

Рішення: кожен домен володіє **одним експортованим об'єктом стану**
(`world`, `clock`, `camera`, `uiState`, `creatureState`, `audioState`,
`tileBuffer`…), чиї **поля** мутуються звідусіль без обмежень ES-модулів —
працює так само, як спільні змінні в оригіналі, але з чіткою пропискою
"хто власник". Масиви (`particles`, `animals`, `clouds`, `tornados`…)
експортовані як `const` і мутуються через `push`/`splice`/`.length = 0` —
теж без переприв'язки. Це дало розбити файл на модулі майже без ризику
поведінкових розбіжностей — переважна більшість функцій перенесена
дослівно, лише з заміною `globalVar` на `store.globalVar`.

## Структура

```
src/
  world/       рельєф і його стан: генерація, шум, біоми, константи
  sim/         клітинкова симуляція: вогонь/ріст/лава, погода, тули гравця,
               природні події (блискавка/метеор/смерч), годинник (час доби/вітер)
  creatures/   довідник видів, спавн/життєвий цикл, AI (мозок тварин), рендер тварин
  civ/         цивілізації: раси, жителі з професіями, міста, королівства,
               дипломатія й війни, їхня графіка
  render/      камера, палітра, текстурний буфер ландшафту, композиція сцени
  audio/       синтезований звук (Web Audio API): рушій, ефекти, фонові звуки
  ui/          DOM-інтерфейс: вкладки/інструменти, HUD, огляд тварини, ввід
  save/        серіалізація світу в localStorage
  main.ts      точка входу: ініціалізація + головний цикл (requestAnimationFrame)
```

### world/
Джерело істини про клітинки сітки: `state.ts` тримає всі типізовані масиви
(`hgt`, `cover`, `biome`, `snow`, `wet`, …) в об'єкті `world`, індекс
клітинки — `y*W+x`, як і в оригіналі. `generate.ts` — процедурна генерація
(fBm-шум із `noise.ts`) висоти/температури/вологості/біомів і початкових
дерев. `constants.ts` — пороги висот, типи покриву/біомів, швидкості росту.

### sim/
`clock.ts` — час доби, вітер, пауза, струс камери/спалах. `simulate.ts` —
клітинковий автомат ландшафту (поширення вогню, тління, застигання лави,
танення снігу, ріст лісу), тікає раз на `TICK` мс, а не щокадру.
`particles.ts` — дощ/сніг/дим/пара/іскри (фізика, без малювання).
`clouds.ts` — фонові й грозові хмари, намокання землі. `events.ts` —
блискавка/метеор/смерч (одноразові події, що б'ють по рельєфу й тваринах).
`tools.ts` — пензлі гравця (`applyTool`) і диспетчер "пострілових"
інструментів (`shootAt`). `worldLifecycle.ts` — оркестрація народження й
перегенерації світу.

### creatures/
`species.ts` — довідник видів (дієта, швидкість, зір, розмноження) — 20+
видів: травоїдні, хижаки, морські, повітряні. `art.ts` — мультяшні векторні
малюнки кожного виду (пози ходьби й "лежить"), з яких species.ts робить
`LodSprite`-и. `emotes.ts` — емоції в бульбашках над тваринами.
`types.ts` — тип `Animal` (стан-машина з набором необов'язкових полів під
кожен стан AI). `habitat.ts` — предикати місцеперебування/їжі, спільні для
спавну й AI. `animal.ts` — народження/спавн/смерть/вибір тварини кліком.
`ai.ts` — "мозок": стани (`wander/eat/drink/flee/stalk/chase/mate/follow/…`),
хижацтво, розмноження, польоти (орел, метелики, кажани, світлячки).
`render.ts` — малювання тварин (дзеркалення за напрямком, м'яка тінь) і
емоцій над ними.

### civ/
Розумні народи — окремий шар над світом, що живе сам по собі.
- `races.ts` — 4 раси: люди, ельфи (лучники, садять ліс), гноми (гори, міцні,
  видобувають камінь), орки (агресивні, плодючі, живуть у наметах); кольори,
  характер і генератор імен міст/держав/жителів.
- `types.ts`/`state.ts` — `Unit` (житель), `City`, `Kingdom`, `Relation`;
  списки й хроніка подій; просторова сітка `forNear` для пошуку ворогів.
- `buildings.ts` — будівлі живуть у сітці як `world.bld` (раса × тип:
  ратуша, замок, хатина, будинок, вежа, поле), територія — `world.owner`
  (id міста + 1). Тому вогонь, лава, метеорит, смерч і "Чисто" руйнують
  міста звичайними механіками клітинок, а малює їх `render/vegetation.ts`
  тим самим атласом, що й дерева.
- `units.ts` — "мозок" жителя за завданнями (не інстинкти, як у тварин):
  професія (фермер, лісоруб, каменяр, мисливець, будівельник, воїн, король)
  → піти → попрацювати → віднести в місто. Уночі мирні ховаються вдома.
  Бій: воїни/король б'ють сильніше, ельфи стріляють з лука.
- `cities.ts` — економіка (їжа/дерево/камінь), кілька будов одночасно,
  перебудова хатина → будинок → вежа і ратуша → замок, народжуваність,
  розподіл професій під потреби, рівні село → містечко → місто → мегаполіс,
  поселенці засновують нові міста, облога й захоплення, руїни. Тік ~1 с.
- `diplomacy.ts` — думка королівств одне про одного (раса, агресивність,
  кордон, випадковість), союзи, війна/мир, союзники вступають у війну,
  захоплення міст, повстання далеких провінцій, падіння королівств. Тік ~4 с.
- `art.ts`/`render.ts` — векторні жителі (одяг кольору королівства,
  інструмент професії) і будівлі кожної раси; кордони королівств (зводяться в
  зображення світу), підписи й прапори міст, стріли, світло у вікнах уночі.
- `actions.ts` — інструменти гравця (вкладка "Народи"): заснувати народ,
  розбрат, мир, огляд жителя/міста. `index.ts` — щокадровий `civFrame()` і
  стартові народи для нового світу. UI — `ui/civPanel.ts` (хроніка, панель
  держав, текст огляду).

### render/
`context.ts`/`camera.ts` — canvas і математика камери (zoom/pan/pinch,
екран↔тайл). `palette.ts` — кольори рельєфу за висотою/біомом.
`cartoon.ts` — інструменти мультяшного малювання (`Painter`: контур у два
проходи + об'ємна заливка, око, пляма). `sprite.ts` — `LodSprite`: векторний
малюнок, растеризований на вимогу в кількох роздільностях (без мерехтіння при
зменшенні). Світ складається з шарів, які зводяться в одне зображення раз на
тік (`buffer.ts`) — лише ті плитки 8×8, які шари позначили зміненими
(`dirty.ts`), бо у великому світі з містами щось змінюється постійно:
- `terrain.ts` — рельєф з білінійно інтерпольованої висоти (плавні береги),
  межі біомів класифікуються по субпікселях, пороги смуг згладжені 2×2
  суперсемплінгом; перемальовується лише там, де змінилась висота;
- `effects.ts` — сніг/лід/згарище/лава/вогонь/мокра земля: поле розмивається
  й "загострюється", тож плями мають плавні криві краї з темним обідком;
  перераховуються лише змінені плитки 8×8;
- `vegetation.ts` — векторні дерева, декор і будівлі цивілізацій: здалеку
  запечені в шар (зміни шукаються третиною рядків за тік), зблизька малюються
  чіткими спрайтами щокадру;
- території королівств (`civ/render.ts`) — між ефектами й будівлями.
`scene.ts` — фінальна композиція кадру: світ → тіні хмар → тварини → смерчі →
частинки → метеорити → хмари → ніч/світло → блискавки → курсор.

### audio/
Увесь звук синтезований у браузері (осцилятори + шумовий буфер), без жодного
аудіофайлу. `engine.ts` — примітиви Web Audio (тон, шумовий постріл,
петлі). `sfx.ts` — каталог конкретних ефектів і голосів тварин.
`ambient.ts` — фонові звуки (цвіркуни, тріск вогню) і гучність петель
(океан/вітер/дощ/вогонь/смерч/лава) залежно від того, що видно в кадрі.

### ui/
`tabs.ts` — вкладки категорій інструментів. `icons.ts` — векторні іконки
інструментів (той самий `Painter`; тварини беруть іконку зі свого малюнка).
Стиль — `src/style.css`: кремові панелі, товстий контур, "тверда" тінь під
кнопками, світла й темна теми через CSS-змінні. `hud.ts` — кнопки шапки (рух/пензель/день-ніч/звук/пауза/
збереження/новий світ) і текстові індикатори (час, вітер, кількість тварин).
`inspect.ts` — панель огляду обраної тварини. `input.ts` — вказівник:
малювання, "постріл", панорама, pinch-zoom, колесо. На сенсорі дія стартує
з затримкою 80 мс (щоб розпізнати другий палець), але швидкий тап теж
спрацьовує — тварина/метеорит/блискавка з'являються з одного дотику. `state.ts`/`toast.ts` —
дрібний спільний стан UI без залежностей (щоб уникнути циклів імпортів).

### save/
`save.ts` — серіалізація рельєфу (шари клітинок у base64; дробові шари
квантовані до 8/16 біт), спрощеного списку тварин і цивілізацій (королівства,
стосунки, міста, жителі) у `localStorage`. Рядок стискається gzip-ом
(`CompressionStream`, префікс `gz:`) — великий світ займає ~1–1.5 МБ замість
кількох. Кнопки 💾/📂 у шапці. Формат версійний (`version: 2`; версія 1
теж відкривається — без народів).

## Що навмисно не змінено

- Усі числові константи (пороги висот, швидкості, ймовірності) перенесені
  дослівно — це "відчуття" симуляції, міняти їх не варто без явного запиту.
- Дивні на вигляд деталі оригіналу (наприклад, `frame`/`fc` заморожуються на
  паузі, через що HUD-оновлення може почати спрацьовувати щокадру) збережені
  як є, а не "виправлені" — вони не впливають на геймплей.
- Зміна розміру вікна лише масштабує камеру, а не перегенеровує світ (як і
  в оригіналі). Розмір самого світу гравець обирає в меню "Новий світ" (↻):
  Малий — як екран, Середній — ×1.5, Великий — ×2 по кожній стороні
  (`WORLD_SIZES` у `world/generate.ts`, площа текстури обмежена ~7.5 Мпкс).
  У більшому світі пропорційно більше тварин і хмар (`world.popK`).

## План розвитку

Нижче — напрямок, у якому може рости симуляція, від найпростішого до
найскладнішого. Кожен пункт спирається на вже наявну архітектуру доменів.

### 1–4. Люди, села, королівства, війни — зроблено (`src/civ/`)
Базова версія вже є: раси, жителі з професіями, міста з економікою й
рівнями до мегаполіса, поселенці, королівства з дипломатією, союзами,
війнами, захопленням міст і повстаннями. Куди рости далі:
- **Кораблі** — зараз народи на різних островах не можуть воювати й
  заселяти одне одного; потрібні човни (новий тип юніта на воді).
- **Дороги й стіни** — дороги вже "протоптуються" через `grazed`; можна
  робити справжні бруковані дороги між містами і мури навколо міст.
- **Торгівля** — каравани між дружніми містами (обмін деревом/каменем/їжею
  підвищує думку королівств).
- **Культура й релігія** — віра як ще одна ознака (крім раси), що впливає
  на дипломатію; храми як нова будівля.
- **Сили бога для народів** — благословення (швидше ростуть), прокляття,
  "божевілля" (місто нападає на своїх), подарунок ресурсів.
- **Взаємодія зі звірами** — хижаки нападають на людей, люди приручають
  худобу (корови/вівці біля ферм).

### 5. Збереження — від локального слоту до повноцінних збережень
Поточний `save/save.ts` — це відправна точка (один слот, `localStorage`).
Далі:
- **Кілька слотів** і мініатюра світу (рендер `tileBuffer` у маленький PNG
  для прев'ю збереження).
- **Експорт/імпорт у файл** (`.json`, можливо стиснутий) — щоб можна було
  ділитися світами між пристроями/людьми.
- **Автозбереження** з інтервалом, з відкатом при пошкодженому файлі.
- Формат уже розширено цивілізаціями (`version: 2`); нові сутності (кораблі,
  дороги) — нові секції в `SavedCiv`.
- Довгостроково — синхронізація збереження в хмару (потребує бекенду, поза
  межами цього фронтенд-проєкту).
